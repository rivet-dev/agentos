# Executor stabilization goal

Status: active. The executor refactor is not ready to merge.

## Objective

Resolve the remaining stability, security, compatibility, memory, performance,
and packaging priorities for the existing V8-default executor refactor. Keep
the branch current with main, preserve its fixes, and produce a reviewable draft
PR backed by validation of the final artifacts. Continue finding, recording,
reproducing, and fixing new issues until the merge gates below are satisfied.

The previous ten-hour minimum is complete. This goal is driven by completion
criteria, with no new time or token budget specified.

## Scope and constraints

- Reuse the existing revision, workspace, bookmark, and draft PR. Preserve
  unrelated work and do not move another workspace's checkout to inspect it.
- Keep V8 as the default. Wasmtime and Binaryen remain opt-in and absent from
  default builds, checks, and tests. Browser execution remains out of scope.
- Preserve the kernel, driver, executor-contract, and concrete-engine boundaries;
  retain the minimal embedded VM dependency and binary-size gates.
- Keep default model-provider endpoints removed. External networking is denied
  by default; VM-local networking and IPC continue to work with Docker-like
  semantics.
- Upgrade the hosted integration to the current authenticated RivetKit/engine
  stack, as explicitly authorized. Use supported scoped JWT authentication for
  workers and independently verify actor authorization; control-plane checks
  alone do not establish actor security. Test invalid signatures, expiry and scope.
- Include the complete hosted server/client repair and checked examples. The
  latest direction to fix all remaining priorities supersedes the earlier
  narrower scope questions. Recover and adapt real implementations and generate
  clients from the actual server contract; do not invent wire APIs, restore
  deprecated transports, or move runtime policy into clients.
- Include curl HTTP/2, HTTP/3, and SFTP/SCP support, with real upstream software
  and owned sysroot/runtime fixes where needed. Git over SSH and HTTPS and real
  GNU awk remain required. Do not substitute implementations or silently defer
  protocols while claiming completion.
- Keep product versions, package namespaces, and TypeScript/Rust client parity
  consistent with repository instructions. Do not deploy a hosted service or
  merge the PR as part of this goal.
- Use Sol subagents for scoped implementation and testing, and Astra for
  independent security and architecture review. Coordinate file ownership and
  builds. Freeze measured artifacts during benchmarks and lifecycle runs.

## Work loop

1. Fetch and inspect main without moving other checkouts. Rebase the existing
   change when needed; review relocated fixes and prove affected behavior.
2. Reproduce the next highest-priority issue with a bounded failing-first test
   or controlled measurement. Use native Node/Linux/Docker behavior as the
   reference where applicable, and record the exact contract being tested.
3. Fix the owning layer. Independently review the change and its tests, including
   cancellation, stale work, partial failure, resource ownership, and isolation.
4. Run focused checks, then the relevant integrated gates. Preserve failures;
   do not loosen limits or change workloads to manufacture a pass. Saturation
   probes stay outside default suites unless they exercise a cheap safeguard.
5. Freeze and hash release binaries, SDKs, software, and benchmark harnesses.
   Run quiet paired comparisons without overlapping builds or artifact mutation.
   Sustained lifecycle/resource tests retain their original bounds and record
   ambient activity separately; they do not establish relative performance.
   Rebuild and repeat affected gates after material changes.
6. Update this issue register, the validation record, and private case notes.
   Send short Slack updates at milestones and for concrete blockers. Ask only
   about genuinely new unresolved decisions; continue independent work while
   awaiting an answer.
7. After local validation and public-diff review, update the existing draft to
   obtain required candidate CI. Keep the draft and all unresolved merge gates
   explicit while CI and remaining performance, upstream-delivery and security
   work continue. A draft update is not merge acceptance.

## Tracking newly discovered issues

- Add every new priority as a new `STAB-###` row before it can be lost in a
  subagent handoff. Record priority, expected/actual behavior, owning component,
  reproduction, affected revision/artifact, evidence, next action, and status.
- Use statuses: suspected, reproduced, fixing, fixed pending validation,
  verified, denied, or blocked. Explain blocked and denied dispositions; keep
  disproved hypotheses and original failures in the case log.
- Reopen verified issues when later changes invalidate their evidence. A fix is
  not verified merely because source was ported or a test command ran zero tests.
- Keep sensitive evidence and upstream issue mappings private. Use anonymous
  fixtures in source and documentation. Do not comment on, close, create, or link
  GitHub issues to the PR. If external engineering tickets are needed, use Linear.
- Maintain the durable post-merge follow-up list for previously reviewed upstream
  issues. Verify the merged artifact and obtain follow-up authorization before
  making public issue updates; do not mark issues resolved from unmerged work.
