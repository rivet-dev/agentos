agentOS runs JavaScript and TypeScript on native V8 inside the VM, backed by a
real Node.js surface: `node:fs`, `node:child_process`, sockets, and npm.

Running a multi-step operation as code instead of chaining one host call per step is called
[Code Mode](https://blog.cloudflare.com/code-mode/). It has a few advantages over
driving [Bash](/agentos/docs/bash):

- **Fewer tokens**: Ten chained operations cost one round trip, not ten.
- **Type checking**: Validate generated TypeScript before you run it.
- **Real data processing**: `map` and `filter` instead of `jq` and `awk`.
- **Parallelism**: `Promise.all` instead of shell job control.

## Evaluate an expression

`evaluate()` returns a JSON-serializable value.

<CodeGroup>

```ts Hosted @nocheck
import { createAgentOsClient } from "@rivet-dev/agentos";

const client = createAgentOsClient({ endpoint: "https://api.rivet.dev" });
const vm = client.agentOS.getOrCreate(["my-vm"]);

const sum = await vm.v1.javascript.evaluate({ expression: "1 + 2" });
console.log(sum.value); // 3
```

<CodeSnippet file="examples/js-quickstart/src/index.ts" title="Library" />

</CodeGroup>

Returning `undefined`, a function, a symbol, or a circular value fails with
`evaluation_serialization_failed` rather than silently losing the value.

`evaluate()` returns as soon as the expression's promise settles and its
in-flight host calls finish. Work it leaves behind is released as described in
[Keep state between calls](#keep-state-between-calls).

## Execute code

`execute()` runs source and captures its output instead of returning a value.

<CodeGroup>

```ts Hosted @nocheck
import { createAgentOsClient } from "@rivet-dev/agentos";

const client = createAgentOsClient({ endpoint: "https://api.rivet.dev" });
const vm = client.agentOS.getOrCreate(["my-vm"]);

const result = await vm.v1.javascript.execute({
	source: `console.log("hello from agentOS")`,
});
console.log(result);
```

<CodeSnippet file="examples/js-sdk-overview/src/index.ts" title="Library" />

</CodeGroup>

Executions are ephemeral, so capture stdio only when you want it: `"stderr"` for
diagnostics, `"all"` for both streams. `onStdout`/`onStderr` stream live and work
independently of capture.

Without a `contextId`, `execute()` behaves like `node -e`: it finishes when the
event loop is empty, so a ref'd timer or a listening server keeps it running
until `timeoutMs`. Call `unref()` on handles that must not hold it open, or use
`spawn` for long-lived work.

## Keep state between calls

Pass a `contextId` to keep one V8 isolate and its global state alive across
calls.

<CodeSnippet file="examples/js-sdk-overview/src/contexts.ts" title="Library" />

A call in a context completes when its top-level code, including any promise it
awaits, settles. It does not wait for work it leaves behind. Globals stay, so the
next call sees the state, but agentOS releases what would keep a Node process
alive:

- **Ref'd timers and immediates** are cancelled and never run. A promise that
  waits on one never settles.
- **Ref'd sockets, servers, and child processes** are closed. Pending I/O on them
  fails with `ERR_AGENTOS_CONTEXT_HANDLE_RELEASED`, never a clean end. A `fetch`
  that is still in flight rejects with that error as its `cause`, and reading a
  stored `Response` body fails the same way.
- **Unref'd timers and handles** are left alone, but nothing runs between calls,
  so they only make progress while a later call is running.

The call's stderr names what was released. Errors raised during that cleanup,
such as an unhandled rejection from a released `fetch`, are written to the same
stderr and never change the call's result. Finish I/O inside one call, and run
long-lived servers with `spawn` instead of a context.

If cleanup is interrupted, agentOS preserves the call's result, reports the
cleanup failure on stderr, and invalidates the context. Later calls fail with
`ERR_AGENTOS_CONTEXT_INVALIDATED`. Close that context and create a new one before
running more code.

Each call starts with a fresh process exit status and exit-request state.
Setting `process.exitCode` or calling `process.exit()` affects that call; later
calls start normally. Globals, process configuration, and registered event
listeners remain in the context.

A context runs one call at a time. A call made while another call in the same
context is still running fails immediately with `execution_busy`. Files, npm,
Bash, and type checks may pass the same id, but they run in fresh processes and
never touch retained memory.

JavaScript defaults to `format: "module"`. Each call is a separate root ES
module, so its imports, top-level declarations, and exports are scoped to that
call. Put values on `globalThis` when a later call in the same context needs
them. For REPL-style script semantics where top-level lexical declarations stay
visible, pass `format: "commonjs"` consistently for that context.

Create the context explicitly before use; an unknown id fails instead of silently
starting fresh state. A context pins to the first inline language that used it,
though JavaScript and TypeScript intentionally share one isolate.

Contexts live until the VM is disposed. They are in-memory state, so they do
not survive a library VM recreated from the same `database`, or a hosted VM's
sleep and wake. Create them lazily on first use.

## Type check before running

Executing TypeScript transpiles it without a semantic check, so validate
generated code explicitly.

<CodeGroup>

```ts Hosted @nocheck
import { createAgentOsClient } from "@rivet-dev/agentos";

const client = createAgentOsClient({ endpoint: "https://api.rivet.dev" });
const vm = client.agentOS.getOrCreate(["my-vm"]);

// Type checking validates generated code before it executes.
const checked = await vm.v1.typescript.check({
	source: `const total: number = "not a number";`,
});
console.log(checked);
```

## Install npm packages

<CodeGroup>

```ts Hosted @nocheck
import { createAgentOsClient } from "@rivet-dev/agentos";

const client = createAgentOsClient({ endpoint: "https://api.rivet.dev" });
const vm = client.agentOS.getOrCreate(["my-vm"]);

await vm.v1.javascript.npm.install({});
```

<CodeSnippet file="examples/js-sdk-overview/src/npm.ts" title="Library" />

</CodeGroup>

Installs modify the VM-wide filesystem, so a package installed once is importable
by every later execution in that VM, in any language. Only one npm/Python
mutation runs at a time per VM; a concurrent install fails with `execution_busy`.

## Background processes and web servers

`spawn` starts a long-lived process and returns a handle. From there you get
stdin, output, signals, and waiting.

<CodeGroup>

```ts Hosted @nocheck
import { createAgentOsClient } from "@rivet-dev/agentos";

const client = createAgentOsClient({ endpoint: "https://api.rivet.dev" });
const vm = client.agentOS.getOrCreate(["my-vm"]);

const server = await vm.v1.javascript.spawn({
	source: `
		import http from "node:http";
		http.createServer((req, res) => res.end("ok")).listen(3000, "127.0.0.1");
		await new Promise(() => {});
	`,
});

// The listener stays inside the VM. No host port is exposed.
const response = await vm.v1.network.fetch({
	request: { port: 3000, path: "/health" },
});
console.log(response.status); // 200

await vm.v1.process.signal({ process: server, signal: "SIGTERM" });
```

<CodeSnippet file="examples/js-dev-servers/src/index.ts" title="Library" />

</CodeGroup>

Spawned processes always start with fresh state, so they take no `contextId`.

## Host functions

Guest JavaScript calls [host functions](/agentos/docs/host-functions) as async globals, so host
credentials stay outside the VM. The globals exist in every guest Node process,
whether it runs inline code, a spawned script, `node` from the shell, or a child
process. Host functions are library-only.
