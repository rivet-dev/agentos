## Monitor executions

Subscribe before creating the schedule when the first event matters.

The example subscribes on an owned connection, observes events for five seconds,
and disposes the connection in `finally`. The caller retains the VM handle.

`cron.fired` contains either a process handle or a bounded `error` with `code`
and `message`. A schedule validated against an older configuration revision
fails with `revision_conflict`; replace the schedule after updating configuration.
The execution follows the same limits, permissions, and output policy as
`process.spawn`. Listed jobs use `nextRunAtMs` and `lastRunAtMs` Unix timestamps
in milliseconds.

## List and cancel schedules

Use `cron.list({})` to inspect jobs and `cron.cancel({ name })` to remove one.
The example cancels its own schedule in `finally`.

## Heartbeat pattern

Use a small shell command for periodic maintenance or checks.

The example schedules `echo heartbeat` once per minute. Use a unique schedule
name for each maintenance task and set `maxHistory` to bound retained history.

Embedded Core also has an in-process cron helper, but its jobs only run while
the embedding process and VM are alive.
