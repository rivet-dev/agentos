title: "Node.js Compatibility"
description: "Review the Node.js built-in modules and compatibility guarantees available to JavaScript and TypeScript code running inside agentOS VMs."
---

Guest JavaScript never touches the host Node.js runtime.

- Every `node:` `import`/`require` resolves to a VM-backed bridge or an
  in-isolate implementation.
- Unknown or denied modules fail explicitly with `ERR_ACCESS_DENIED`.
- The guest reports Node.js `v22.0.0` via `process.version`.

How builtins are backed:

- **VM-backed** — routes through the VM filesystem, sockets, processes, DNS, or
  entropy.
- **In-isolate** — pure JavaScript running inside V8; no host access.
- **Denied** — importing throws `ERR_ACCESS_DENIED`.

<Note>A guest never falls through to a real host builtin. Anything not bridged
or implemented in the isolate is denied.</Note>

## VM-backed builtins

| Module | Backed by |
| --- | --- |
| `fs`, `fs/promises` | VM filesystem: fds, streams, metadata, symlinks, polling watchers. |
| `child_process` | VM process table. `spawn`, `exec`, `execFile`, sync variants. Explicit `uid` and `gid` use guest credentials: root can drop privileges; unauthorized changes fail with `EPERM`. Direct commands check execute and directory-search permissions with the child identity; interpreter inputs such as `node script.js` require read permission. |
| `net`, `dgram` | VM TCP, Unix-socket, and UDP tables. |
| `dns`, `dns/promises` | VM DNS resolver. |
| `http`, `https`, `http2`, `tls` | VM socket/TLS paths: clients, servers, pooling. |
| `os` | VM-scoped platform, arch, hostname, CPU, memory, user. |
| `crypto` | RSA JWK import/export, `KeyObject.from(CryptoKey)`, RSA-OAEP hash and label options, entropy, hashes, HMAC, ciphers, scrypt, UUIDs, WebCrypto, bounded unbiased integers with `randomInt`, and constant-time byte comparison with `timingSafeEqual`, including genuine cross-realm buffers and byte views. |
| `process` | VM env, cwd, live kernel PID/PPID, signals, timers, stdio, umask. Sequential top-level processes retain their own identities when a VM is reused. |
| `module` | `createRequire`, builtin resolution, basic `Module` compat. |
| `console` | Bounded formatting, guest stdout/stderr. |
| `readline`, `sqlite`, `tty` | VM-backed compatibility surfaces. |
| `timers`, `timers/promises` | Timeout, interval, immediate, promise variants. |
| `stream/web`, `stream/consumers`, `stream/promises` | Web Streams and stream helpers. Queuing strategies, readers, writers and controllers share their constructor identity with the corresponding globals. |

- Network builtins obey the VM [permission policy](/agentos/docs/permissions).
- Network access is **denied until granted** by the VM creator.

HTTP server requests expose `iterator()` and `Symbol.asyncIterator` over their
bounded request body. Headers dispatch before upload EOF; fixed-length and
chunked bodies stream with backpressure. `iterator({ destroyOnReturn: false })`
preserves the request when the consumer returns early; observing EOF completes
normal cleanup. The parser limits headers to 64 KiB and bodies to 128 MiB.
`Server.close()` and `Server.closeIdleConnections()` reap idle HTTP keep-alive
connections and preserve active response bytes through TCP shutdown.
`Server.closeAllConnections()` closes active and idle HTTP connections;
upgraded connections remain owned by the application.

Trusted embedded callers can connect to a VM-local TCP listener through
`vm.network.connect(port)`. Reads and writes remain in the VM socket table;
this API cannot connect to a host listener. Await each operation in its
direction and close the handle when finished. Writes split into at most 64 KiB
messages with backpressure. Rust exposes the same operations through
`AgentOs::network_connect` and its connection's `read`, `write`, `end` and `close`.
There are at most 256 published streams per VM. Raw TCP reads have no HTTP
request deadline; closing the handle or disposing the VM cancels them. A
published client retains buffered data after its guest server process exits.
Guest socket and descriptor APIs cannot access that trusted client handle.

Unix datagram socketpairs drop empty messages in the latest qualified native
comparison. A correction retaining empty message records and charging bounded
queue metadata awaits native qualification. UDP readiness and ignored-stdin EOF
have separate controls.

Blob and File construction defaults to a64MiB byte ceiling and1024 parts.
Trusted VM creators can set `limits.jsRuntime.maxBlobBytes` within the configured
V8 heap budget. V8 external-memory accounting still applies to every allocated
buffer. The effective default is lower for a smaller VM heap. Guests cannot
change this policy; excess bytes fail with `ERR_BLOB_SIZE_LIMIT` before the
constructor copies the parts.

## In-isolate builtins

- Full: `path`, `buffer`, `events`, `stream`, `util`, `assert`,
  `querystring`, `string_decoder`, `punycode`, `constants`, `sys`.
  Default and named ESM imports supported.
- Compression: `zlib` exposes gzip/deflate and a native Rust Brotli codec within
  the isolate boundary. Brotli synchronous and callback APIs accept byte input;
  stream adapters buffer input until finish, with a default 32 MiB bound set by
  `AGENTOS_BROTLI_MAX_BUFFERED_BYTES`. Output obeys the bridge response limit
  and `maxOutputLength`. Progressive Brotli flush is unsupported.
- URL: `url` exposes WHATWG constructors and legacy helpers. Formatting a
  WHATWG URL currently loses credentials and ignores formatting options in the
  latest qualified native runtime. An owning formatter correction has Node
  source controls; rebuilt guest qualification remains pending.
- Async context: `AsyncLocalStorage` and `AsyncResource` in `async_hooks`
  behave as in Node.js, including across native `await`, promises, timers, and
  callbacks from sockets, servers, child processes, and signals. Overlapping
  calls do not see each other's store.
- Contexts: `vm` supports `createContext`, `isContext`, `Script`, and the
  `runInContext`, `runInNewContext`, and `runInThisContext` methods. Context
  objects and their returned globals share property updates. Getter failures
  preserve the original thrown value; this intentionally differs from Node.js
  24, which can suppress those failures. Errors retain their actual filename,
  line, and column information. `compileFunction` and `measureMemory` remain
  unsupported, and `Script.createCachedData()` returns an empty buffer.
- Feature-detection shims: `createHook` and the async ID functions in
  `async_hooks`, `diagnostics_channel`, `perf_hooks`, `worker_threads`,
  `v8`. `worker_threads` does **not** create real worker threads.

`v8.serialize` and `deserialize` use the current isolate's native V8 wire
format. They preserve cyclic/shared graphs, `Map`, `Set`, `Date`, bigint,
undefined, regular expressions, typed views, and Node Buffers. Typed views
serialize only their visible bytes, including Buffers backed by a larger pool.
Compatible Node.js versions can read and write these buffers. Functions,
symbols, and unsupported host objects still fail to clone. Native V8 semantics
apply, including invoking enumerable property getters during serialization.
Serialized input and output are bounded by `limits.reactor.maxBridgeResponseBytes`.
The former JSON-only compatibility format is no longer accepted; it was not a
Node.js serialization format. `Deserializer` maintains its cursor and shared
references across reads, including subclass `_readHostObject` callbacks, raw
reads, and transferred ArrayBuffers. Retained readers use the existing
`limits.reactor.maxCapabilities` and `limits.reactor.maxBlockingBytes` budgets.
The low-level `Serializer` class remains partial.
`structuredClone` transfers ArrayBuffers only after validating the transfer list and cloning the graph. Duplicate, detached, and unsupported transfer entries fail with `DataCloneError`; failed clones leave their source buffers attached.

CJS and ESM share these implementations. `getHeapStatistics()` reads live
statistics for the current V8 isolate, with byte-valued sizes and integer
counters. These values are not process RSS or whole-sidecar memory usage.
`getHeapSpaceStatistics`, `getHeapCodeStatistics`, `getCppHeapStatistics`, and
heap-snapshot helpers remain compatibility placeholders; they do not provide
real measurements or snapshots.

## Denied builtins

`cluster`, `domain`, `inspector`, `repl`, `trace_events`, `wasi`.

Fork IPC remains experimental. Its transport uses a dedicated kernel descriptor,
bounded frames and notifier-driven readiness. Message, error and disconnect
callbacks and ordinary stdin/stdout lifetime still require native qualification;
compiling the transport alone does not establish Node compatibility. Older builds
multiplex control frames through standard streams and couple stdin EOF to IPC.
The latest native comparison still exposes an ignored-stdin EOF mismatch.
Its kernel correction requires rebuilt qualification; message isolation alone
does not establish correct fd0 EOF behavior.

## Global APIs

- Modern web globals: `fetch`, `Headers`, `Request`, `Response`,
  `TextEncoder`/`TextDecoder`, `Buffer`, URL APIs, `Blob`, `File`, `FormData`,
  abort APIs, `structuredClone`, `performance`, WebAssembly.
- `CompressionStream` and `DecompressionStream` support `gzip`, `deflate` and
  `deflate-raw` through the guest zlib implementation. Readers pause compressed
  output when their queue fills. Cancellation and abort propagate shutdown to both
  Web stream endpoints, including reasonless cancellation.
  Invalid writes and genuine cross-realm buffer input have additional source
  corrections awaiting native qualification. The same applies to shadowed
  view metadata in `timingSafeEqual`, callback-style `TestContext.after`, and
  `randomInt` callback arguments and validation order.
- Global `Performance` and `node:perf_hooks.Performance` describe the same
  runtime-owned clock and User Timing instance. Direct construction is illegal.
  `toJSON()` serializes the VM clock's `timeOrigin`; native process timing and
  event-loop utilization fields are not included. Performance EventTarget
  methods and resource timing records remain unsupported.
- `fetch()` uses VM sockets and follows the same policy as `http`/`net`.
- `Uint8Array` has `toHex`, `toBase64`, `fromHex`, `fromBase64`, `setFromHex`,
  and `setFromBase64`, with the `alphabet`, `omitPadding`, and
  `lastChunkHandling` options.
  Encoded results use the VM memory budget; oversized results fail before allocation.
- V8 supports finalized WebAssembly exception handling with `exnref`
  (`try_table`, `throw_ref`) in every VM. Remove the old host setting
  `AGENTOS_V8_WASM_EXNREF=0` before upgrading. A sidecar configured to
  disable this feature fails startup with `ERR_AGENTOS_UNSUPPORTED_V8_OPTION`.

## `node:sqlite`

- `new DatabaseSync(path)` opens a database in the VM filesystem.
- JavaScript numbers bind as SQLite REAL values; `bigint` binds as INTEGER.
  Floating-point parameters and results preserve their IEEE 754 bits.
- SQL `ATTACH DATABASE` and `VACUUM INTO` targets accept only the literal
  `:memory:` or an empty temporary name. Other filenames, URIs, parameters,
  and expressions fail with an authorization error, including paths in the VM.
  Plain `VACUUM` continues to work.
- `PRAGMA writable_schema` has no effect. Process-wide SQLite pragmas
  (`data_store_directory`, `hard_heap_limit`, `soft_heap_limit`, and
  `temp_store_directory`) fail with an authorization error.

## Modules and output

- ESM and CommonJS both use the VM filesystem and normal `node_modules`
  resolution.
- Console/stream output flows through the bounded process-output path — see
  [Processes & Shells](/agentos/docs/processes).

Explicit `node --expose-gc` (or `NODE_OPTIONS=--expose-gc`) enables `globalThis.gc()` for that guest process. Collection runs on its owning V8 isolate; it does not collect other VMs or the host heap. `{ execution: "async" }` returns a promise after collection.

Node child processes inherit the calling process environment when `options.env` is omitted. An explicit environment replaces it, including an empty object; `fork()` follows the same rule. VM bootstrap metadata remains separate from guest-visible environment values.


Trusted embedded callers can set `createSidecar({runtime:{blocking:{maxQueuedBytes}}})`
to size the process-wide blocking operation budget. The default remains64MiB,
and native admission enforces the selected budget. Shared pool users must select
matching runtime settings. Rust callers use `create_sidecar_with_runtime` or
`get_shared_sidecar_with_runtime` with `AgentOsSidecarRuntimeConfig`.


Composed abort signals propagate even when an ordinary abort listener stops event
propagation. Unused composed signals can be collected; an observed signal stays
live while its sources can still abort. EventTarget listener limits and the
per-call `AbortSignal.any()` input limit remain enforced.
