## Mounts

The actor's filesystem configuration is a closed registry. By default, each VM
uses an ephemeral in-memory overlay over the bundled base image. Its writes
survive for that VM's lifetime but are discarded when the VM is replaced. Use
an `actor-sqlite` root or mount when files must survive VM replacement. Unknown
backends, JavaScript VFS objects, callbacks, and host paths are rejected.

The runtime creates missing standard POSIX directories before sealing a read-only
root. Existing files, symlinks, and directory metadata are preserved. TypeScript
and Rust use the same directory defaults. Native host roots keep their existing
layout.

`O_TMPFILE` works on the default in-memory root filesystem. Custom writable
mounts can return `EOPNOTSUPP`; use an exclusive named temporary file when a
mount does not support anonymous files.

Large-file streaming is a follow-up. Current actions enforce bounded payloads
and fail with a typed limit error.

## Embedded API

Embedded Core uses the same in-memory root filesystem and accepts trusted custom
mounts. Read more in the
[embedded API quickstart](/agentos/docs/quickstart-embedded).
