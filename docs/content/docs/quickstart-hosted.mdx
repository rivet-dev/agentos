Hosted agentOS runs as the `agentOS` Rivet Actor. Its configuration and files in
an `actor-sqlite` mount persist when the VM sleeps. Your client can reconnect to the same VM by key or
ID. To run a VM inside your Node.js process, use the
[library quickstart](/agentos/docs/quickstart).

## Connect to a worker

Build the native worker with the `hosted` feature and start its `actor` entrypoint
against your Rivet control plane. Keep the worker and SDK at the same agentOS
version. Configure the endpoint, namespace, and token for your environment; the
SDK does not provision or deploy the worker.

```bash
cargo build --release -p agentos-sidecar --features hosted
RIVET_ENDPOINT="$RIVET_ENDPOINT" RIVET_NAMESPACE="$RIVET_NAMESPACE" \
RIVET_POOL="$RIVET_POOL" RIVET_TOKEN="$RIVET_NODE_TOKEN" \
  target/release/agentos-sidecar actor
```

Use a matching Rivet 3.0.7 control plane, configure the namespace and node pool,
and set `RIVET_NODE_TOKEN` to a node JWT issued by your backend. A node credential
registers the worker; an application credential controls which VMs callers can
reach. Never send the admin token or the worker token to an end user.

The `node` grant permits registration in this namespace. The worker
also needs the shown actor grants to use its shared preload coordinator. Rotate
the node credential before expiry and reconnect the worker with its replacement.

## Write a file and run a command

The generated client mirrors the Rust actor registry. Actions are grouped as
`vm.filesystem`, `vm.process`, and `vm.network`. The key passed to
`getOrCreate` identifies one durable VM.

Run the checked example from the repository:

```bash
RIVET_ENDPOINT="$RIVET_ENDPOINT" RIVET_NAMESPACE="$RIVET_NAMESPACE" \
RIVET_POOL="$RIVET_POOL" RIVET_TOKEN="$RIVET_APPLICATION_TOKEN" \
  pnpm --dir examples/hosted start
```

This backend quickstart needs `actor:create` and `actor_gateway:create/read`
permissions in its namespace. Resolving an ID does not convert subsequent
keyed actions into ID-scoped requests. It explicitly persists `/workspace` with
an `actor-sqlite` mount.

## Give a caller access to one VM

After your backend authenticates a caller and checks ownership of a VM, issue a
short-lived token for that existing Actor ID. This token grants access to the
agentOS actions on that VM, not to another VM or VM creation. Application roles
and ownership decisions remain in your backend; the worker token is separate.
Rivet 3.0.7 allows 30 s of clock skew after a token's expiry timestamp.
Account for that allowance when choosing short token lifetimes.

Disposing the client closes its connections. It does not destroy the durable VM.
Hosted configuration accepts remote package URLs and serializable filesystem
descriptors. Host callbacks, host directory mounts, and local package paths are
available only to trusted embedded callers.

See [the hosted API](/agentos/docs/hosted-api) for action groups and
[hosted limits](/agentos/docs/actor-limits) for transfer and execution bounds.

## Embedded API

Use `AgentOs.create()` when your process should own the VM lifecycle and trusted
host integrations. Read more in the
[embedded API quickstart](/agentos/docs/quickstart-embedded).
