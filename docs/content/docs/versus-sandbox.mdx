title: "agentOS vs Sandbox"
description: "Choose between lightweight agentOS VMs, full external sandboxes, or a combined architecture based on isolation, compatibility, and workload needs."
skill: true
---

- **agentOS** is a lightweight VM that runs inside your process. Near-zero cold start, low memory, direct backend integration via [bindings](/agentos/docs/bindings).
- **Sandboxes** are full Linux environments with root access, system packages, and native binary support.
- **Embedded applications can compose both.** Embedded Core can register a full
  sandbox through trusted host bindings and mounts. The static hosted actor does
  not expose those host capabilities.

## Comparison

|  | agentOS VM | Full Sandbox |
|---|---|---|
| **Cost** | Very low. Runs in your process. | Pay per second of uptime. |
| **Startup** | Near-zero cold start (~6 ms). | Seconds to spin up. |
| **Backend integration** | Direct. [Bindings](/agentos/docs/bindings) call your functions with zero latency. | Indirect. Requires network calls back to your backend. |
| **Credentials** | Embedded [bindings](/agentos/docs/bindings) keep credentials on the host. Hosted VMs use serializable config. | Must be injected into the sandbox environment. |
| **Permissions** | Granular, deny-by-default. | Coarse-grained (container-level). |
| **Infrastructure** | Static actor binary or embedded Core | Vendor account + API keys. |
| **Best for** | Coding, file manipulation, scripting, API calls, orchestration. | Browsers, desktop automation, native compilation, dev servers. |

## When to use each

### agentOS VM

Use the lightweight VM for isolated command and language workloads:

- Coding and file editing
- Running scripts and CLI tools
- Calling APIs and services via bindings
- Durable command workflows
- Tasks where backend integration matters (permissions and tool access)

### Full sandbox

Spin up a sandbox when the workload needs a real Linux kernel:

- Browsers and desktop automation (Playwright, Puppeteer, Selenium)
- Heavy compilation and native toolchains
- Dev servers with hot reload, databases, and system ports
- GUI applications and VNC sessions

### Both together

Embedded applications can use agentOS with
[external sandboxes](/agentos/docs/sandboxes) when a workflow needs both:

- Guest code runs in the agentOS VM with access to configured bindings and permissions
- Sandbox spins up on demand for heavy tasks
- Sandbox filesystem is mounted into the VM as a native directory
- Guest code reads and writes sandbox files the same way it reads local files

This composition requires trusted in-process callbacks and is therefore not a
hosted actor feature.
