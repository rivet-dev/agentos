## Components

| Component | Trust | What it does |
| --- | --- | --- |
| Client | Trusted | `@rivet-dev/agentos-core` in your backend, or the hosted `agentOS` actor behind the HTTP API. Starts and controls the sidecar. |
| Sidecar | Trusted | A Rust process that runs separately from your application and hosts the kernel and every guest executor. |
| Kernel | Trusted | Owns the process table, the virtual filesystem and its mounts, the socket table, pipes, PTYs, permissions, and resource limits. |
| Guest executors | Untrusted | V8 isolates run JavaScript and TypeScript. WebAssembly runs the shell, coreutils, Python, and other compiled commands. |

The library starts and owns the sidecar from your backend. When hosted, the
`agentOS` actor owns the same sidecar and you control it over the
[HTTP API](/agentos/docs/hosted-api). The client is a thin transport: VM
defaults, permission policy, package projection, and filesystem setup all live
in the sidecar, so library and hosted VMs behave the same.

## A virtualized kernel

The entire kernel is virtualized. Every file, process, and network operation a
guest makes is a syscall into the kernel, which checks it against the VM's
permissions and limits before acting. Guest processes are entries in the
kernel's process table, not host processes, and guest sockets are entries in
its socket table, not host sockets.

By default the VM behaves like a Docker container with no host mounts and no
published ports. Guest code can use its virtual filesystem, spawn guest
subprocesses, and listen on guest sockets, but it can't reach host files,
processes, or environment variables. Outbound network access is limited to a
default allowlist. You opt in to more host access with
[mounts](/agentos/docs/filesystem#mounts),
[host functions](/agentos/docs/host-functions), and
[network permissions](/agentos/docs/permissions#network). See the
[Security Model](/agentos/docs/security-model) for the full trust boundary.

## Guest runtimes

The WebAssembly guest is a Linux-in-WebAssembly environment, a POSIX superset
of WASI. The kernel supplies real `fork`, `exec`, `wait`, signals, file
descriptor and socket tables, a shell, and coreutils through host imports, so a
program written for Linux runs unmodified when it is built for an available
runtime. See [POSIX Syscalls](/agentos/docs/architecture/posix-syscalls).

JavaScript and TypeScript run in V8 isolates with Node.js-compatible APIs whose
filesystem, process, and network calls go through the same kernel. See the
[JavaScript Executor](/agentos/docs/architecture/javascript-executor) and
[Node.js Compatibility](/agentos/docs/javascript-compatibility).

Software is installed as `.aospkg` packages projected under `/opt/agentos`, with
commands linked under `/opt/agentos/bin`. See
[Packages & Command Resolution](/agentos/docs/architecture/packages-and-command-resolution).

## Sidecar transport

The library talks to the sidecar over stdio and a Unix socket. The sidecar
reads requests from fd 0 and writes ordinary events to stdout. An inherited
socket on fd 3 carries responses, host callbacks, heartbeats, and shutdown
control.

The library may keep host-only state the sidecar can't access, such as host
function handlers, mount plugins, local package paths, and custom scheduling.

## Durability

The default VM root is an ephemeral in-memory overlay over the bundled base
image. Store the root filesystem in the VM's SQLite database for files that
must survive VM recreation. See [Persistence](/agentos/docs/persistence).

The VM database has independent schema owners. Each owner advances only its own
migration ladder.

| Owner | Namespace |
| --- | --- |
| Filesystem | `agentos_fs_*` |
| Core | `agentos_core_*` |
