`process.exec` runs a command to completion. `process.spawn` starts a
long-running process and returns a process ID for wait, signal, stdin, PTY
resize, and bounded output replay.
`process.get` and `process.list` report `startedAtMs`; nodes returned by
`process.tree` report `startTimeMs` and `exitTimeMs`. These are Unix timestamps
in milliseconds. Completed tree nodes use the same structured `exit` status as
`process.get`. Tree timestamps record when agentOS first observed the process
or its exit, not exact kernel lifecycle times. `exitTimeMs` can be absent when
agentOS did not observe the exit.
`process.tree` includes guest child processes as well as processes launched
through Core. Guest and tracked display PIDs can overlap; use the returned
process ID rather than reconstructing one from a node's `pid`.
For untracked guest nodes, `args` is the kernel's runtime argument list. For
example, Node's `-e` source is passed to its runtime separately, so the tree
shows `-e` but not the source text.

Process arguments are passed as individual argv entries. An empty string is a
valid argument; it is not dropped or treated as an omitted argument. Empty
commands or working directories are invalid input, including when opening a
terminal.

Use `onProcessOutput` and `onProcessExit` for live events. Replay retained
output after reconnecting to the same durable VM.

Interactive terminals are separate resources under `terminal.open`,
`terminal.stdin.write`, `terminal.pty.resize`, `terminal.output.read`,
`terminal.wait`, and `terminal.close`. Their live events are
`terminal.output` and `terminal.exit`.

A process wait returns an exit code only after agentOS observes a
guest exit. A rejected launch or lost exit observation rejects the wait instead
of inventing an exit code. An observation failure does not prove the guest has
stopped; inspect the VM or restart it before assuming it is safe to retry work.
With output retention enabled, Core output callbacks include the sidecar's
optional `sequence` and `timestampMs` metadata for correlating live output with
replay. Local diagnostics without a guest output event omit this metadata.
Ordinary-process replay returns `exitCode` when the sidecar has confirmed exit
and reconciles Core's `wait`, `get`, and `list` state, even if the live exit
notification was missed.
Real-terminal replay also reconciles `wait_shell` after a missed exit event or
an earlier observation failure. TypeScript Core's local prompt terminal does
not provide replay.

## Embedded API

Starting VM disposal rejects pending execution admission, completion, and
result waits with `ERR_AGENTOS_VM_DISPOSED`. TypeScript Core uses `dispose`;
Rust Core uses `shutdown` and returns `ClientError::VmDisposed`. New execution
waits on that VM also fail. Other VMs on the shared sidecar keep running, and
results already returned to the caller remain usable.

Wait rejection does not confirm that guest code has stopped. Await VM disposal
to confirm native cleanup; disposal can still report a teardown error.
