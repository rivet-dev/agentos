`process.run` runs an executable and explicit argument array to completion.
Run `sh` with `-c` explicitly when shell parsing is required.
`process.spawn` returns a
generation-scoped process ID for `get`, `wait`, `signal`, stdin, PTY
resize, and bounded output replay.
`process.get` and `process.list` report `startedAtMs`; nodes returned by
`process.tree` report `startTimeMs` and `exitTimeMs`. These are Unix timestamps
in milliseconds. An embedded process retains its SDK PID in tree queries while it
remains in the bounded process registry, including after output routing is
released or the guest process is reaped. Completed tree nodes use the same structured `exit` status as
`process.get`. Tree timestamps record when agentOS first observed the process
or its exit, not exact kernel lifecycle times. `exitTimeMs` can be absent when
agentOS did not observe the exit.
`process.tree` includes guest child processes as well as processes launched through
the actor. Only nodes with a `process` handle can be used with actor control and
output-replay actions; other nodes are inspectable but not controllable through
those actions. Guest and tracked display PIDs can overlap; use the provided
`process` handle rather than reconstructing one from a node's `pid`.
For untracked guest nodes, `args` is the kernel's runtime argument list. For
example, Node's `-e` source is passed to its runtime separately, so the tree
shows `-e` but not the source text.

In both embedded clients, awaiting `process.tree()` queries the VM's current
process snapshot. If the query fails, the call rejects rather than returning
previously cached state.

Process arguments are passed as individual argv entries. An empty string is a
valid argument; it is not dropped or treated as an omitted argument. Empty
commands or working directories are invalid input, including when opening a
terminal.

Use a RivetKit connection for live `process.output` and `process.exit`
events. Replay retained output with `process.output.read` after reconnecting.

Interactive terminals are separate resources under `terminal.open`,
`terminal.stdin.write`, `terminal.pty.resize`, `terminal.output.read`,
`terminal.wait`, and `terminal.close`. Their live events are
`terminal.output` and `terminal.exit`.
The default terminal runs an interactive `sh` inside the VM, with pipelines,
redirection, history, and completion. Its working directory and exported
environment remain available to later commands until the terminal closes.

Exit status records the guest's actual terminal reason. A process terminated by
`SIGTERM` reports exit code `143` and signal `SIGTERM`; a normal `exit(143)`
reports the same code without a signal. If a process catches `SIGTERM` and exits
successfully, its status reports code `0` without a signal. Sending a signal does
not itself complete a wait. Live exit events, retained output, process queries,
and waits use the same observed status. Standard signals use their POSIX names;
observed signals 32 through 64 use numeric strings.

Embedded TypeScript `process.wait` returns structured status with `exitCode`,
optional numeric `exitSignal`, and an optional signal name. Rust
`wait_process_exit` returns the code and numeric signal together; `wait_process`
returns the code. For embedded terminals, TypeScript `terminal.waitExit` and Rust
`wait_shell_exit` return full status, while `terminal.wait` and `wait_shell`
return the code.

An embedded process wait completes only after agentOS observes a guest exit. A rejected launch or lost exit observation rejects the wait instead
of inventing an exit code. An observation failure does not prove the guest has
stopped; inspect the VM or restart it before assuming it is safe to retry work.
